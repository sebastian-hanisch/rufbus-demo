# `ruf_results.json`: Schlüssel der vorgerechneten Messreihe

Erzeugt von `tools/dump_results.py` aus `auswertung.json` (`tools/analyse.py`), das aus den Rohdaten von `tools/sweep_ruf.py`, `sweep_line.py`, `sweep_exact.py` entsteht (Rohdaten liegen nicht im Repo). Generator: ganzzahlig (SplitMix64, Raster 5..95); 30 Zufalls-Seeds (1..30) je Zelle. UTF-8, Zahlen auf 6 gültige Stellen gerundet. Sonderwerte: `"inf"` = nicht erreichbar bzw. (bei Kipppunkten) kein Kipppunkt, der Rufbus ist im ganzen Bereich billiger; `"-inf"` = der Linienbus ist schon an der Untergrenze der Messreihe billiger; `null` = NaN/nicht gebildet. Dichte = Anfragen je Stunde und km² (Gebiet 10 x 10 km: Anfragen/h = 100 x Dichte); Dichtestufen 0,03 / 0,06 / 0,10 / 0,15 / 0,20 / 0,30 / 0,40 / 0,60 / 0,80 / 1,00. Dichte-Schlüssel in Objekten als Text, z. B. `"0.4"`. Kosten sind Fahrzeugstunden je bedientem Fahrgast (kein Euro).

| Schlüssel | Bedeutung, Einheit |
|---|---|
| `n_cells`, `n_runs`, `seeds_per_cell`, `scan_*` | Zahl der Rufbus-Zellen (202), Einzelläufe (je ein K), Zufalls-Seeds je Zelle ({"30": 202}); `scan_total` Seed-Zellen (6060), `scan_edge_low` / `scan_censored`: Fälle, in denen die Flottensuche am unteren Rand stoppt bzw. nie besteht (beide 0) |
| `ruf_base` | Liste (10 Dichten): Rufbus-Basis (FCFS, Kapazität 4, Umweg 1,5, W=15 min, 10x10 km, 30 Haltepunkte, Hub 50 %). `K_mean/K_se/K_med/K_p10/K_p90` Mindestflotte K* für 90 % Servicegrad (Fahrzeuge); `n_req` Anfragen im Messfenster; `wait/ride/total` mittlere Warte-/Fahr-/Gesamtzeit (min); `detour` Fahrzeit / Direktzeit; `served` Servicegrad; `util` Flottenauslastung; `shared` Anteil mit Mitfahrern; `corider` mittlere Mitfahrer; `occ` Besetzung beim Fahren (Fahrgäste); `cost` [Mittel, SE, n] Fahrzeugstunden je Fahrgast (Flotte), `cost_med/p10/p90`; `busy_cost` dasselbe nur mit gefahrenen Stunden; `wait_p90` P90 der Wartezeit (min) |
| `power_law_exponent` | Exponent a in K* ~ λ^a (Anpassung über 10 Dichten), ohne Einheit |
| `line_design_waitmatched` | je Dichte und Entwurf (R, S1-S4, P1, P2): `mean` mittlere Fahrzeugzahl N* des Linienbusses bei gleicher mittlerer Wartezeit wie der Rufbus (nur erreichte Seeds), `n_inf` Seeds ohne Erreichen bis N=30, `med` Median (Fahrzeuge) |
| `ruf_ks_by_seed` | je Dichte: `seeds` (1..30), `K` K* je Zufalls-Seed, `N_R`, `N_S2`, `N_P1` N* je Seed für die Entwürfe R, S2, P1 beim Maß „gleiche mittlere Wartezeit“ (`"inf"` = bis N=30 nicht erreicht) |
| `line_quality_R` | Liste (10 Dichten): Einzellinie R bei N* (wartegleich): `N`, `takt` (min), `cycle` Umlaufzeit (min), `wait/ride/total` (min), `transfer_share`, `rho` Lastfaktor, `env_15_1.5` / `env_25_2` Anteil im Zeitrahmen (W min, Umweg f) |
| `line_by_N` | `R` und `S2`: Liste je Fahrzeugzahl N (4, 6, 8, 10, 12, 16, 20, 24, 30) bei Dichte 0,4: `takt`, `wait`, `ride`, `total` (min), `transf`, `env` (Anteil im Rahmen 25 min / 2,0), `env_strict` (15 / 1,5), `rho` |
| `env_line_R` | je Versprechen `W_f` (z. B. `15_1.5`): Liste (10 Dichten) von [Seeds ohne Erfüllung bis N=30, mittleres N* der erfüllenden Seeds] für Linie R |
| `cross` | Liste (31 Kipppunkt-Läufe, `label` benennt Variante oder Qualitätsmaß). `crossing` Hauptwert: Dichte (Anfragen/h/km²), bei der Rufbus- und Linienbus-Kosten gleich werden (bester Linienentwurf je Instanz); `crossing_kind` (`wert`/`kein`/`unter`) sagt, was gemeint ist; `lam_cross` dasselbe in Anfragen/h (mit L²); `crossing_cell` bester Entwurf je Dichte-Zelle; `crossing_fixed/oracle`; `crossing_by_design` (+ `_kind`) Kipppunkt je festem Entwurf; `boot_p10/p90` Bootstrap-Band (300 Resamples, `boot_seed` 12345), `boot_share_none/lowedge` Anteil der Resamples ohne Kipppunkt bzw. mit Linie schon an der Untergrenze billiger; `ruf_mean` Rufbus-Kosten je Dichte (Mittel), `ruf_cost_p10/p90` P10/P90 über die Seeds; `line_mean_oracle` / `line_mean` / `line_mean_fixed` Linienbus-Kosten (bester Entwurf je Instanz / je Dichte-Zelle / ein fester Entwurf `design_fixed`); `line_mean_by_design` {Entwurf: Kosten je Dichte, Mittel über Seeds, `"inf"` wenn mindestens ein Seed unerreichbar}; `line_unreach_by_design` Zahl unerreichbarer Seeds; `ruf_inf` Seeds, in denen der Rufbus im Suchbereich nicht erreichbar war; `design_per_dens` bester Entwurf je Dichte; `L` Gebietsseite (km) |
| `ratio_band` | je Maß (`wait` gleiche mittlere Wartezeit, `total30/35/40/45` mittlere Gesamtreisezeit ≤ 30/35/40/45 min) und Linienwahl (`best` bester Entwurf je Instanz, `R`, `S2`, `P1`): `D` Dichten, `p10`, `med`, `p90` des Verhältnisses Rufbus-Kosten / Linienbus-Kosten je Fahrgast über die Zufalls-Seeds (Linie unmöglich → 0; Rufbus unerreichbar → `"inf"`) |
| `proc_vs_fcfs` | je Verfahren (`ols`, `batch`, `batch0`): Liste (10 Dichten) mit `K_fcfs`, `K_proc` (mittleres K*), `diff_mean/diff_se` K*-Differenz zu FCFS (Fahrzeuge, gepaart je Seed), `less/same/more` Seeds mit weniger/gleich/mehr, `served_diff_at_Kfcfs/served_diff_se` Servicegrad-Differenz bei K*(FCFS) |
| `batchB` | Batchfenster B (min) und Dichte als `B_dichte`: [K*-Differenz zu FCFS, SE] (Fahrzeuge) |
| `noise`, `noise_all` | Rauschgrenze: Batch-Suche mit zweitem Suchzufall; je Dichte `K_mean_absdiff`, `K_p95`, `K_zero_share` (Anteil identisches K*), `served_p95` (Servicegrad-Punkte); `noise_all` über alle (n=90) |
| `pooling` | Liste (10 Dichten): für `c4_f1.5`, `c8_f1.5`, `c4_f2.0` je `shared`, `corider`, `occ`, `K` bei K* |
| `cap_f` | Liste (10 Dichten): K*-Differenz zu c=4, f=1,5 als [Mittel, SE, Seeds abweichend] für `c8_f1.5`, `c4_f2.0`, `c8_f2.0` und (soweit gemessen) `c1_f1.5`, `c2_f1.5`, `c3_f1.5` |
| `pool_effect` | Liste (10 Dichten): `K_c1/c2/c4/c8` mittleres K*, `cost_c*` Fahrzeugstunden je Fahrgast, `saving_c4_vs_c1` Flottenersparnis durch Bündeln (Anteil) |
| `curves` | Servicegrad-Kurven bei Dichte 0,06 / 0,2 / 0,6: `ruf_<d>`: {K: [Servicegrad, SE, Seeds]}; `line_R_<d>`, `line_S2_<d>`: {N: [Anteil im Rahmen 25 min / 2,0, mittlere Wartezeit min]}, gekürzt auf N ∈ {2, 4, 6, 8, 10, 12, 14, 16, 20, 24, 30} |
| `exact` | je Instanzgruppe `n_K_span_W` (n Anfragen, K Fahrzeuge, Fenster in min, 0 = Los, W in min): `n_inst`, `complete`, `ex_served_mean`, `ex_time_median_ms`, `ex_time_max_s` und je Verfahren `fcfs`, `batch`, `off` (Offline-Heuristik): `served_rel` Anteil des Exakten bedient, `share_all_served_as_exact`, `share_optimal`, `cost_gap_mean_pct/_p90_pct` Kostenlücke bei gleich vielen Bedienten (%), `served_gap_mean/se`, `time_median_ms` |
| `exact_checks` | `heur_beats_exact` (muss 0 sein), `rows`, `flex_better_than_early`, `early_better_than_flex`, `incomplete` (Aufzählung unvollständig), `n` |
| `exact_need` | Los von 8 Anfragen, je W (`"15.0"`, `"30.0"`) und Verfahren (`ex`, `fcfs`, `batch`, `off`): `mean` nötige Fahrzeuge (4 = auch 3 reichen nicht), `n`, `over_exact` Lose, in denen das Verfahren mehr Fahrzeuge als der Exakte braucht |
| `counters` | je Verfahren Summe der Verbesserungsschritte über alle Läufe (`reloc`, `swap`, `retry`, `*_try`, `ins`, `runs`) |
| `meta` | Zahl Läufe/Zellen/Seeds, Rechenzeit (`cpu_time_ruf_runs_s` Summe der Lauf-Zeiten, `wallclock_s` je Sweep), Python- und numpy-Version, Datum, Dichtestufen, Bootstrap-Angaben |
